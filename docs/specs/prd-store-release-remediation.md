## 1. الهدف

تحويل تطبيق ترويئة من الحالة الحالية «غير جاهز» إلى إصدار يمكن تقديمه بصورة مستقلة إلى Google Play وApple App Store، مع حماية حسابات العملاء والأسعار والطلبات، وإصلاح الوظائف المؤثرة، وإنتاج Builds قابلة لإعادة البناء والاختبار.

هذه الوثيقة تحدد ما سينفذه Codex. العمليات التي تحتاج ملكية حساب أو موافقة قانونية أو جهازًا غير متاح تبقى بوابات يقدمها المالك، ولا يتم التحايل عليها.

## 3. المتطلبات الوظيفية

- تصبح قاعدة البيانات المصدر الموثوق للهوية والأسعار والخصومات والرسوم وحالات الطلب والدفع.
- يكون إنشاء الطلب واستهلاك الكوبون عملية ذرية وقابلة لإعادة المحاولة دون تكرار.
- يمنع العميل من قراءة أو تعديل بيانات عميل آخر أو أي إعداد سري أو وظيفة إدارية.
- تحتفظ السلة بنسخ ثابتة من خيارات المنتج، وتمسح الكوبون والمنطقة صراحة عند الإزالة.
- يشتق Checkout حقول التوصيل من نوع الاستلام الحالي ويمنع الأوقات غير الصالحة والخيارات المطلوبة الناقصة.
- تعرض عمليات الإدارة النجاح بعد تأكيد الخادم فقط.
- تكتمل الاستعادة والحذف والإشعارات والعناوين والتقارير والمشاركة والطباعة بمسارات فشل واضحة.
- تكون موارد Android وiOS متتبعة أو مولدة بصورة حتمية.
- تصبح إعدادات التوقيع والـCapabilities والصلاحيات وPrivacy Manifests قابلة للفحص في الحزم النهائية.
- تعمل روابط الخصوصية والشروط والدعم والحذف، وتوجد حماية للمحتوى الذي ينشئه المستخدم.

## 4. المتطلبات غير الوظيفية

### الأمن

- لا يوجد Secret أو مفتاح توقيع أو كلمة مرور داخل Git أو Logs أو Artifacts عامة.
- جلسة Auth لا تُحفظ في Preferences عادية بعد اكتمال خطة الترحيل.
- كل صلاحيات الإدارة والخطوات المالية مفروضة على الخادم، وليس على Router فقط.
- تسجل العمليات الحساسة دون بيانات شخصية أو Tokens.

### الاعتمادية

- إرسال الطلب Idempotent عند الضغط المتكرر أو فقدان الرد.
- فشل الشبكة لا يظهر كنجاح ولا يفقد بيانات نموذج قابلة لإعادة المحاولة.
- كل Stream وTimer وSubscription يُغلق عند انتهاء Cubit.

### الأداء وتجربة الاستخدام

- لا يظهر Jank مستمر في التمرير على جهاز Android تمثيلي.
- قياس Startup والصور واستعلامات التقارير قبل اعتماد الإصدار؛ تُحدد الحدود الرقمية بعد توفر الجهاز والبيانات التجريبية.
- RTL والنص الكبير ولوحة المفاتيح وحالات التحميل والخطأ تعمل على الشاشات الحرجة.

### الجودة

- `flutter analyze --fatal-warnings --fatal-infos` ينجح دون مشاكل.
- فحص التنسيق غير الكتابي ينجح.
- جميع اختبارات الوحدة والـWidget تنجح دون حذف أو Skip لإخفاء الفشل.
- كل عيب يتم إصلاحه بدورة Red → Green → Refactor واختبار Regression.
- Android وiOS لهما بوابتا بناء مستقلتان في CI.

## 5. القيود التقنية

- الحفاظ على Flutter وBLoC وget_it وLayer-Based Clean Architecture و`Either<Failure, T>`.
- لا تُستدعى DataSource أو Repository مباشرة من Screens.
- لا يتم تعديل Migration مطبق باعتباره وسيلة وحيدة للإصلاح؛ تُستخدم Migration أمامية قابلة للمراجعة، مع تنظيف المصدر والتاريخ في إجراء منفصل.
- لا تُجرى ترقية جماعية للمكتبات. الترقيات تكون محددة بسبب أمني أو توافق متجر ومع اختبارات رجوع.
- لا تُحفظ مفاتيح Android أو Apple أو Supabase داخل المشروع.
- لا يتم تغيير مخطط إنتاج أو إعادة كتابة Git history أو النشر دون موافقة المالك ونسخة احتياطية وخطة رجوع.

## 6. خارج النطاق

- شراء حسابات المتاجر أو دفع الرسوم.
- تدوير المفتاح من حساب Supabase نيابة عن المالك دون جلسة مصرح بها.
- اعتماد النص القانوني النهائي بدل المالك أو مستشاره.
- ادعاء نجاح iOS دون Mac وXcode وiPhone/iPad.
- تنفيذ دفع مالي حقيقي أو إرسال رسائل WhatsApp لعملاء حقيقيين.
- إعادة تصميم التطبيق بالكامل أو إضافة وظائف تجارية غير مرتبطة بالجاهزية.
- النشر الإنتاجي الآلي قبل نجاح Internal Testing وTestFlight وموافقة المالك.

## 7. الاعتماديات والبوابات الخارجية

- وصول مصرح إلى مشروع Supabase الصحيح وبيانات اختبار لعميلين ومدير.
- تأكيد المالك لتدوير المفتاح وسياسة الحذف والاحتفاظ.
- ملفات العلامة التجارية والأيقونات التي يوافق عليها المالك.
- Upload Key وحساب Google Play يظلان تحت سيطرة المالك.
- Mac مع Xcode 26+ وحساب Apple Signing وأجهزة iPhone/iPad للاعتماد النهائي.
- بيانات الدعم والدول والفئة العمرية وسياسات الخصوصية المعتمدة.

## 8. أسئلة لا تمنع بدء العمل المحلي

- ما رابط مشروع Supabase الصحيح؟
- هل يريد المالك الإبقاء على التعليقات العامة في الإصدار الأول أم إخفاءها حتى اكتمال Moderation؟
- ما مدة الاحتفاظ القانونية ببيانات الطلبات بعد حذف الحساب؟
- ما الدول الأولى وبيانات الدعم الرسمية؟
- هل الطباعة الحرارية جزء إلزامي من الإصدار الأول؟

يمكن بدء إصلاحات الاختبارات والكود المحلي دون إجابة هذه الأسئلة، لكن لا تُغلق المراحل التي تعتمد عليها.

- [✓] آثار API وقاعدة البيانات والبناء الأصلي موثقة.
- [✓] الاعتماديات الخارجية وبوابات المالك محددة.
- [✓] الأسئلة المفتوحة لا تمنع بدء الإصلاح المحلي، ولا تُفترض إجاباتها داخل التنفيذ.
